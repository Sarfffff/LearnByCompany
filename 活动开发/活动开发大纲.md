# 元梦之星活动系统完整开发指南
## 一、活动系统概述

活动系统是元梦之星游戏的核心系统之一，负责管理游戏内各类限时活动、商业化活动、节日活动等。系统采用模块化、模板化设计，支持快速开发和复用。

### 1.1 系统架构

活动系统主要由以下部分组成：
- **配置层**：Excel配置表（H_活动中心配置.xlsx）
- **数据层**：NewActivityModel（活动数据管理）
- **UI层**：基于UMG的界面系统，支持继承和组件化
- **协议层**：活动数据下发、红点推送、通用协议
- **任务系统**：活动任务数据管理（TaskSystemModel）

### 1.2 目录结构

根据iwiki文档目录，活动系统文档包含80个文档，主要分为：
- 活动开发指南
- 活动实例（商业化活动）
- 模板与组件
- 具体活动实现文档
- 活动改造与优化

## 二、活动开发流程

### 2.1 完整开发流程（从零开始）

#### 第一步：活动配置

所有活动都需要在 **H_活动中心配置.xlsx** 及其分表中进行配置。

**核心配置表：**

1. **活动页签表**
   - `id`：一级页签ID
   - `seq`：页签顺序
   - 控制活动在发现中的分类显示

2. **活动配置表**（最重要）
   - `id`：活动ID（唯一标识，必填）
   - `activityNameType`：活动类型枚举（同类型活动共享）
   - `showInCenter`：是否展示在活动中心
   - `tagId`：所属页签ID（必填）
   - `labelId`：活动在页签内的排序（必填）
   - `activityUIDetail`：关联的UMG界面文件名（必填）
   - `timeInfo`：活动时间（beginTime, endTime, showBeginTime, showEndTime）
   - `activityTaskGroup`：任务组ID数组（分号分隔）
   - `activityShopType`：商城ID（如有兑换商店）
   - `clientParams`：客户端显示参数（字符串数组）
   - `rewardInfo`：活动奖励 {itemId:itemNum}
   - `jumpId`/`jumpType`：跳转配置
   - `pakGroupId`：分包ID（如需分包下载）
   - `activityGroup`：活动分组（区分主玩法/副玩法）

3. **活动任务组表**
   - 一个活动包含一个或多个任务组
   - 每个任务组包含一个或多个任务
   - 配置任务有效期、任务类型

4. **活动红点配置表**（H_红点配置.xlsx）
   - `playerLevel`：玩家等级限制
   - `registerDays`：注册天数限制
   - `redDotType`：红点显示类型（0:所有 1:可领奖 2:上新）

#### 第二步：资源准备

**Layout视角（UI资源）：**

1. **活动资源存放路径**

Feature/System/Script/System/Activity/  
├── Public/ # 模板化活动模板逻辑  
├── Instance/ # 模板化活动实例逻辑  
└── HistoryActivity/ # 旧版本活动逻辑

2. **资源组织规范**
- 每个活动创建独立文件夹（便于分包下载）
- Layout资源 → `Blueprints/` 文件夹
- 图片资源 → `Texture/` 文件夹
- **禁止**直接引用其他活动文件夹的资源

2. **通用组件存放路径**
Feature/System/Script/System/Activity/Public/Component/
多个活动复用的组件放入此目录
#### 第三步：数据协议对接

**核心协议（NewActivityModel.lua）：**

1. **活动数据下发**
- 协议：`ActivityListAll_C2S_Msg`
- 触发时机：打开发现或跳转活动
- 处理逻辑：
  -- 请求所有活动列表
  _MOE.NetworkManager:SendMsg(_MOE.MsgName2Id.ActivityListAll_C2S_Msg, {}, 
    function(msg)
      -- 处理活动数据
      self:InitActivityData()
    end)
1. **活动数据解析**
    
    - `InitActivityMap()`：以页签ID为Key缓存活动数据
        
    - 检测活动有效期和显示状态
        
    - 处理PixUI活动和无极大图公告混排  
        
2. **新活动协议**（推荐）
    
    - `ActivityGetAllInfo_C2S_Msg`：通过活动ID获取活动数据
        
    - `ActivityInfoUpdateNtf`：活动数据更新监听
        
    - `ActivityGeneralReqHandle`：活动通用协议（支持自定义msgType）
        
    - `ActivityReceiveRewards_C2S_Msg`：领奖协议  
        
3. **红点协议**
    
    - `ActivityReadDotNtf`：红点数据下发
        
    - `ActivityClickRedDot_C2S_Msg`：红点消除
        
    - `ClearAllRedDot_C2S_Msg`：一键清除红点
        

#### [](https://iwiki.woa.com/p/4014513877#%E7%AC%AC%E5%9B%9B%E6%AD%A5%EF%BC%9Aui%E5%BC%80%E5%8F%91)第四步：UI开发

**UI开发规范：**

1. **基于模板开发**（推荐）
    
    - 继承现有模板（如 `UI_ActivityLottery_BaseView`）
        
    - 重写必要的方法（`GetTAG()`, `PlayEffectItems()` 等）
        
    - 使用父类组件减少重复代码  
        
2. **独立开发**
    
    - 创建新的UMG界面
        
    - 在 `UIWndNameToLuaPath.lua` 中注册
        
    - 实现活动逻辑脚本  
        
3. **UI继承示例**（抽奖活动）  
    

#### [](https://iwiki.woa.com/p/4014513877#%E7%AC%AC%E4%BA%94%E6%AD%A5%EF%BC%9A%E9%80%BB%E8%BE%91%E5%BC%80%E5%8F%91)第五步：逻辑开发

**客户端逻辑（以抽奖活动为例）：**

-- 1. 定义活动Model（如需要缓存数据）
local ActivityLotteryModel = _MOE.Class("ActivityLotteryModel", _MOE.BaseModel)

function ActivityLotteryModel:GetDataSourceRewardList()
    -- 获取抽奖奖励列表
end

-- 2. 在主界面中注册Model
function UI_ActivityLottery_BaseView:GetModel()
    return _MOE.Models.ActivityModel.subModels.ActivityLotteryModel
end

-- 3. 监听活动数据更新
self:AddEventListener(_MOE.Models.NewActivityModel.OnActivityInfoUpdateNtf, 
    self.OnActivityInfoUpdate)

-- 4. 处理任务数据（如有任务）
self:AddEventListener(_MOE.EventEnum.TASK_INFO_MAP_UPDATE_NOTICE, 
    self.OnTaskUpdate)

1. **配置推送**：策划配置完成后推送服务器并reload
    
2. **分包打包**：如配置了 `pakGroupId`，需打包分包
    
3. **功能测试**：
    
    - 活动显示/隐藏
        
    - 时间控制
        
    - 任务完成与领奖
        
    - 红点逻辑
        
    - 中断处理（切页签、杀进程）
        
    - 断线重连
        
### [](https://iwiki.woa.com/p/4014513877#22-%E7%AD%96%E5%88%92%E8%A7%86%E8%A7%92%E9%85%8D%E7%BD%AE%E8%A6%81%E7%82%B9)2.2 策划视角配置要点

1. **活动基础配置**
    
    - 在正确的分表中配置（依据活动类型）
        
    - 必填字段：id, activityNameType, tagId, labelId, activityUIDetail
        
    - 时间配置：注意 showBeginTime/showEndTime 与 beginTime/endTime 的区别  
        
2. **任务配置**
    
    - 任务组需配置在 `activityTaskGroup` 字段（分号分隔）
        
    - 任务组包含任务类型和有效期
        
    - 有效期控制任务是否开放  
        
3. **活动类型与分组**
    
    - `activityType`：服务器使用，需服务器增加枚举
        
    - `activityGroup`：控制显示在主玩法或副玩法发现中
        
    - 枚举值：0=主玩法, 1=农场, 2=MOBA等  
        
4. **换皮活动**
    
    - 复制现有活动配置
        
    - 修改活动有效时间和 `activityUIDetail`
        
    - 推送reload服务器

### [](https://iwiki.woa.com/p/4014513877#23-%E5%AE%A2%E6%88%B7%E7%AB%AF%E8%A7%86%E8%A7%92%E5%BC%80%E5%8F%91%E8%A6%81%E7%82%B9)2.3 客户端视角开发要点

**活动数据管理：**

1. **数据下发流程**
    
    - 打开发现 → 请求 `ActivityListAll_C2S_Msg` → 解析并缓存活动数据
        
    - 数据以活动页签ID为Key进行缓存
        
    - 自动过滤无效页签和过期活动  
        
2. **红点管理**
    
    - 登录成功后下发 `ActivityReadDotNtf`
        
    - 活动变动时重新下发
        
    - 主页面/页签红点由服务器处理
        
    - 界面内红点由客户端自行处理  
        
3. **活动脚本组织**
    
    - 模板活动：`Feature/System/Script/System/Activity/Public/`
        
    - 实例活动：`Feature/System/Script/System/Activity/Instance/`
        
    - 旧活动：`Feature/System/Script/System/Activity/HistoryActivity/`
        
    - 子Model需在 `ActivityModelPath.lua` 中注册  
        
4. **任务系统对接**
    
    - 监听 `_MOE.EventEnum.TASK_INFO_MAP_UPDATE_NOTICE`
        
    - 通过参数 `taskMap` 判断是否为当前活动任务

#### [](https://iwiki.woa.com/p/4014513877#%E7%BA%A2%E7%82%B9%E5%A4%84%E7%90%86%E6%B5%81%E7%A8%8B)红点处理流程

1. **服务器下发红点**
    
    - 协议：`ActivityReadDotNtf`
        
    - 包含：活动ID、红点类型、红点ID  
        
2. **客户端处理红点**
    
    - 主页面/页签红点：服务器自动处理
        
    - 界面内红点：客户端根据活动数据自行判断
        
    - 一次性红点：调用 `ActivityClickRedDot_C2S_Msg` 消除  
        
3. **一键清除红点**
    
    - 第一部分：本地红点（公告、PixUI引导）→ `PlayerModel:SetClientCacheTable`
        
    - 第二部分：服务器红点 → `ClearAllRedDot_C2S_Msg`
        
    - 第三部分：PixUI红点 → 收到 `PixuiRedDotNtf` 后调用 `PixuiRedDotReport_C2S_Msg`

### [](https://iwiki.woa.com/p/4014513877#51-%E5%A4%A7%E5%AF%8C%E7%BF%81%E7%8E%A9%E6%B3%95%E5%AE%9E%E7%8E%B0)5.1 大富翁玩法实现

#### [](https://iwiki.woa.com/p/4014513877#%E6%A0%B8%E5%BF%83%E7%8E%A9%E6%B3%95)核心玩法

玩家投掷骰子，角色在棋盘上前进，踩中格子触发奖励。

#### [](https://iwiki.woa.com/p/4014513877#%E6%A0%BC%E5%AD%90%E7%B1%BB%E5%9E%8B)格子类型

- **奖励格子**：踩中后获得奖励
    
- **跳转格子**：传送到指定位置（前进步数、快速前进）
    
- **抽奖格子**：触发抽奖
    
- **任务格子**：触发任务
    

#### [](https://iwiki.woa.com/p/4014513877#%E6%95%B0%E6%8D%AE%E6%A8%A1%E5%9E%8B)数据模型

```javascript
-- 活动数据
activityData = {
    curIndex = 5,              -- 当前所处格子索引
    finishedStepNum = 12,       -- 已完成步数
    finishedRoundNum = 1,       -- 已完成圈数
    hasReceiveReward = false     -- 是否已领取格子奖励
}
```

#### [](https://iwiki.woa.com/p/4014513877#%E6%8E%B7%E9%AA%B0%E5%AD%90%E6%B5%81%E7%A8%8B)掷骰子流程

1. **客户端发送协议**
    
    - 三种骰子：常规（1个）、双倍（2个）、指定点数
        
    - 协议包含：骰子类型、自选点数（如适用）  
        
2. **服务器返回结果**
    
    - `beforeIndex`：投掷前位置
        
    - `afterIndex`：目标位置
        
    - `step`：点数数组  
        
3. **客户端模拟移动**
    
    - 先播放投掷动画
        
    - 本地计算路径：`CurStandIndex + step`
        
    - 逐格移动，触发经过逻辑
        
    - 到达目标后触发踩中逻辑
        

#### [](https://iwiki.woa.com/p/4014513877#%E8%A7%92%E8%89%B2%E7%A7%BB%E5%8A%A8%E9%80%BB%E8%BE%91)角色移动逻辑

```javascript
-- 移动流程
for i = 1, stepCount do
    -- 1. 移动到下一格
    local nextIndex = self.CurStandIndex + 1
    self:MoveToGrid(nextIndex)
    
    -- 2. 更新步数
    self.finishedStepNum = self.finishedStepNum + 1
    self:UpdateStepUI()
    
    -- 3. 触发经过逻辑（奖励格子）
    if self:IsRewardGrid(nextIndex) then
        self:TriggerPassLogic(nextIndex)
    end
    
    -- 4. 检查是否经过起点（更新圈数）
    if nextIndex == 0 then
        self.finishedRoundNum = self.finishedRoundNum + 1
        self:UpdateRoundUI()
    end
end

-- 5. 触发踩中逻辑
self:TriggerLandLogic(targetIndex)
```

#### [](https://iwiki.woa.com/p/4014513877#%E4%B8%AD%E6%96%AD%E5%A4%84%E7%90%86)中断处理

**切出活动页签再切回：**

1. 请求活动数据
    
2. 根据数据初始化位置和状态
    
3. 检查当前格子是否需要处理（奖励/抽奖）
    

**杀进程/断线重连：**

- 同上，根据活动数据重新初始化

- 农场玩法活动
    
- MOBA玩法活动
    
- 其他独立玩法活动
    

#### [](https://iwiki.woa.com/p/4014513877#%E9%85%8D%E7%BD%AE%E9%9A%94%E7%A6%BB)配置隔离

**activityGroup字段：**

- `0`：主玩法活动（默认）

**发现页显示：**

- 主玩法发现只显示 `activityGroup=0` 的活动
    
- 农场发现只显示 `activityGroup=1` 的活动
    
- 以此类推

    - 副玩法活动资源放在独立目录
        
    - 避免与主玩法资源混淆  
        
2. **协议隔离**
    
    - 副玩法活动数据独立下发
        
    - 避免影响主玩法性能  
        
3. **UI适配**
    
    - 副玩法可能有独立的UI风格
        
    - 需要针对性调整

## [](https://iwiki.woa.com/p/4014513877#%E4%B8%83%E3%80%81%E5%B8%B8%E8%A7%81%E9%97%AE%E9%A2%98%E4%B8%8E%E8%A7%A3%E5%86%B3%E6%96%B9%E6%A1%88)七、常见问题与解决方案

### [](https://iwiki.woa.com/p/4014513877#71-%E6%B4%BB%E5%8A%A8%E4%B8%8D%E6%98%BE%E7%A4%BA)7.1 活动不显示

**可能原因：**

1. **配置问题**
    
    - `showInCenter` 未设置为 true
        
    - `tagId` 对应的页签不在有效期
        
    - `suspend` 字段未设置为 0  
        
2. **时间问题**
    
    - 当前时间不在 `timeInfo` 范围内
        
    - `showBeginTime` 未到或 `showEndTime` 已过  
        
3. **分包问题**
    
    - 配置了 `pakGroupId` 但未下载分包
        
    - 分包下载失败  
        
4. **数据问题**
    
    - 服务器未推送配置
        
    - 客户端未请求到活动数据
        

**排查步骤：**

1. 检查配置表字段
    
2. 检查服务器配置是否推送
    
3. 检查客户端日志（搜索 `NewActivityModel`）
    
4. 检查分包状态
    

---

### [](https://iwiki.woa.com/p/4014513877#72-%E7%BA%A2%E7%82%B9%E4%B8%8D%E6%98%BE%E7%A4%BA%E4%B8%8D%E6%B6%88%E9%99%A4)7.2 红点不显示/不消除

**可能原因：**

1. **红点配置问题**
    
    - 未配置在 `H_红点配置.xlsx` 中
        
    - 玩家等级/注册天数不满足  
        
2. **协议问题**
    
    - 未收到 `ActivityReadDotNtf`
        
    - 红点类型不匹配  
        
3. **逻辑问题**
    
    - 界面内红点需客户端自行处理
        
    - 一次性红点未调用消除协议
        

**解决方案：**

1. 检查红点配置表
    
2. 监听 `NewActivityModel.OnActivityInfoUpdateNtf` 刷新红点
    
3. 一次性红点调用 `ActivityClickRedDot_C2S_Msg`
    
4. 检查 `redDotType` 是否正确

### [](https://iwiki.woa.com/p/4014513877#73-%E4%BB%BB%E5%8A%A1%E4%B8%8D%E6%9B%B4%E6%96%B0)7.3 任务不更新

**可能原因：**

1. **任务组未配置**
    
    - `activityTaskGroup` 字段未填写或格式错误
        
    - 任务组ID不存在  
        
2. **任务有效期问题**
    
    - 任务组不在有效期
        
    - 任务已完成但状态未同步  
        
3. **监听问题**
    
    - 未监听 `TASK_INFO_MAP_UPDATE_NOTICE`
        
    - 监听了但判断逻辑错误
        

**解决方案：**

```javascript
-- 正确监听任务更新
function UI_Activity_TaskPanel:OnTaskUpdate(taskMap)
    if not taskMap then return end
    
    -- 判断是否为当前活动的任务
    local activityInfo = self:GetActivityInfo()
    if not activityInfo or not activityInfo.activityTaskGroup then return end
    
    for _, taskGroupId in pairs(activityInfo.activityTaskGroup) do
        if taskMap[taskGroupId] then
            self:RefreshTaskInfo()
            break
        end
    end
end
```

### [](https://iwiki.woa.com/p/4014513877#74-%E6%8A%BD%E5%A5%96%E6%8A%A5%E9%94%99)7.4 抽奖报错

**可能原因：**

1. **配置问题**
    
    - `activityParam[1]` 抽奖ID不存在
        
    - 抽奖奖池未配置  
        
2. **协议问题**
    
    - 抽奖协议返回错误
        
    - 货币不足  
        
3. **UI问题**
    
    - 抽奖按钮组件未正确配置
        
    - 动效播放失败
        

**解决方案：**

1. 检查抽奖ID和奖池配置
    
2. 检查货币是否足够（按钮红点会提示）
    
3. 检查动效资源是否存在
    
4. 查看协议返回错误码

### [](https://iwiki.woa.com/p/4014513877#75-%E4%B8%AD%E6%96%AD%E5%90%8E%E7%8A%B6%E6%80%81%E5%BC%82%E5%B8%B8)7.5 中断后状态异常

**问题描述：**  
切出活动页签再切回，或杀进程后，活动状态显示异常。

**解决方案：**

1. **初始化时重新请求数据**  
    
    ```javascript
    function UI_Activity_BaseView:OnShow()
        -- 重新请求活动数据
        _MOE.Models.NewActivityModel:ReqGetActivityInfoById(self.activityId, 
            function()
                self:RefreshUI()
            end)
    end
    ```
    
      
    
2. **根据数据恢复状态**
    
    - 角色位置（大富翁类活动）
        
    - 已完成步数
        
    - 已领取奖励状态  
        
3. **处理中断前的操作**
    
    - 检查是否有未领取的奖励
        
    - 检查是否有未完成的抽奖

**排查步骤：**

2. 检查分包是否已打包
    
3. 检查分包是否已下载
    
4. 检查分包内容是否完整

```javascript
-- 检查分包状态
local pakGroupId = activityInfo.pakGroupId

end
```

### [](https://iwiki.woa.com/p/4014513877#94-%E5%B8%B8%E8%A7%81%E9%97%AE%E9%A2%98faq)9.4 常见问题FAQ

**Q：如何快速开发一个新活动？**  
A：优先使用现有模板，继承后重写差异化部分。

**Q：活动配置后为什么不显示？**  
A：检查 `showInCenter`、`tagId`、时间配置、分包状态。

**Q：如何实现活动内红点？**  
A：客户端根据活动数据自行判断，不依赖服务器红点协议。

**Q：副玩法活动如何隔离？**  
A：使用 `activityGroup` 字段，在配置和UI上做隔离。

**Q：活动数据何时清理？**  
A：切换场景时，子Model会自动清理数据。
