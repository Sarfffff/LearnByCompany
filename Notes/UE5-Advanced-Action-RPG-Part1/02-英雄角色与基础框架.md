### [P9 Native Gameplay Tags](https://www.bilibili.com/video/BV12YCrYCE62?p=9)（09:37）

**提交**：`a74dc12 NativeTagsDone`。

文件：`WarriorGameplayTags.h/.cpp`。

```cpp
namespace WarriorGameplayTags
{
    UE_DECLARE_GAMEPLAY_TAG_EXTERN(InputTag_Move);
    UE_DECLARE_GAMEPLAY_TAG_EXTERN(InputTag_Look);
}
```

```cpp
UE_DEFINE_GAMEPLAY_TAG(InputTag_Move, "InputTag.Move");
UE_DEFINE_GAMEPLAY_TAG(InputTag_Look, "InputTag.Look");
```

- C++ 标识符和 Tag 字符串是两层概念。
- `MatchesTag` 支持父子层级；`MatchesTagExact`/`HasTagExact` 要求精确。
- `GameplayTags` 必须进入模块依赖。

> [!warning] `UE_DECLARE_GAMEPLAY_TAG_EXTERN` 的导出写法要以当前 UE5.4 宏定义与模块编译结果为准。声明、定义的命名空间和符号名必须完全一致；链接错误首先检查 `.cpp` 是否编入当前模块，而不是只修改 Tag 字符串。

### [P10 Input Config Data Asset](https://www.bilibili.com/video/BV12YCrYCE62?p=10)（10:30）

**提交**：`f5b4a2a InputConfigDone`。

课程公开最终源码原文：

```cpp
USTRUCT(BlueprintType)
struct FWarriorInputActionConfig
{
    GENERATED_BODY()

    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, meta=(Categories="InputTag"))
    FGameplayTag InputTag;

    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly)
    UInputAction* InputAction;
};
```

建议修正版应显式写成 `UInputAction* InputAction = nullptr;`，否则 UE 结构体反射检查可能报告对象属性未初始化；用户本地工程目前就存在过这一日志错误。

```cpp
UCLASS()
class UDataAsset_InputConfig : public UDataAsset
{
    UInputMappingContext* DefaultMappingContext;
    TArray<FWarriorInputActionConfig> NativeInputActions;

    UInputAction* FindNativeInputActionByTag(const FGameplayTag& InInputTag) const;
};
```

查找算法遍历 `NativeInputActions`，同时检查 Tag 相等和 Action 非空。资产配置：

```text
DA_InputConfig
├─ DefaultMappingContext = IMC_Default
└─ NativeInputActions
   ├─ InputTag.Move → IA_Move
   └─ InputTag.Look → IA_Look
```

> [!bug] 用户当前工程中的 `InputAction` 若未初始化为 `nullptr`，UE 会产生 `ObjectProperty ... is not initialized properly`。结构体对象指针必须显式默认初始化。

### [P11 Custom Enhanced Input Component](https://www.bilibili.com/video/BV12YCrYCE62?p=11)（07:24）

**提交**：`69488a7 Custom input component done`。

```cpp
UCLASS()
class UWarriorInputComponent : public UEnhancedInputComponent
```

核心模板：

```cpp
template<class UserObject, typename CallbackFunc>
void BindNativeInputAction(const UDataAsset_InputConfig* InInputConfig,
                           const FGameplayTag& InInputTag,
                           ETriggerEvent TriggerEvent,
                           UserObject* ContextObject,
                           CallbackFunc Func)
{
    checkf(InInputConfig, TEXT("Input config data asset is null"));

    if (UInputAction* FoundAction = InInputConfig->FindNativeInputActionByTag(InInputTag))
    {
        BindAction(FoundAction, TriggerEvent, ContextObject, Func);
    }
}
```

`DefaultInput.ini`：

```ini
DefaultPlayerInputClass=/Script/EnhancedInput.EnhancedPlayerInput
DefaultInputComponentClass=/Script/Warrior.WarriorInputComponent
```

这是后续 `CastChecked<UWarriorInputComponent>` 成立的前提。

### [P15 Hero Anim Instance](https://www.bilibili.com/video/BV12YCrYCE62?p=15)（09:31）

**提交**：`e7b741d Relax state done`。

课程公开最终源码保留了两处历史拼写：

```cpp
AWarriorHeroCharacter* OwningHeroCharacter;
bool bShouldEnterRelaxState;
float EnterRelaxtStateThreshold = 5.f;
float IdleElpasedTime;
```

对应更新逻辑：

```cpp
if (bHasAcceleration)
{
    IdleElpasedTime = 0.f;
    bShouldEnterRelaxState = false;
}
else
{
    IdleElpasedTime += DeltaSeconds;
    bShouldEnterRelaxState = IdleElpasedTime >= EnterRelaxtStateThreshold;
}
```

用户本地工程已规范化为 `EnterRelaxStateThreshold` 和 `IdleElapsedTime = 0.f`，这是推荐修正版，不是课程仓库原始拼写。

- 必须先调用 `Super::NativeThreadSafeUpdateAnimation`，确保 `bHasAcceleration` 已更新。
- 移动后立即重置计时和 Relax 状态。
- 原课程仓库中存在 `EnterRelaxtStateThreshold`、`IdleElpasedTime` 的历史拼写；用户工程已改为规范名称。

### [P17 Ability Activation Policy](https://www.bilibili.com/video/BV12YCrYCE62?p=17)（11:08）

**提交**：`d871f47 Activation Policy done`。

```cpp
UENUM(BlueprintType)
enum class EWarriorAbilityActivationPolicy : uint8
{
    OnTriggered,
    OnGiven
};
```

`UWarriorGameplayAbility` 覆盖 `OnGiveAbility`：

```cpp
if (AbilityActivationPolicy == EWarriorAbilityActivationPolicy::OnGiven &&
    ActorInfo && !Spec.IsActive())
{
    ActorInfo->AbilitySystemComponent->TryActivateAbility(Spec.Handle);
}
```

`OnGiven` 能力结束后清除自身 Spec：

```text
GiveAbility → OnGiveAbility → TryActivateAbility → EndAbility → ClearAbility
```

适合一次性初始化能力，例如出生时生成武器。`OnTriggered` 能力保留在 ASC，等待输入/事件激活。

### [P20 Start Up Data](https://www.bilibili.com/video/BV12YCrYCE62?p=20)（12:15）

**提交依据**：启动数据类型与 P21 的同步加载在 `d1883dd Sync loading done` 中共同落地；B站将概念拆成两集。

类型：

```text
UDataAsset
└─ UDataAsset_StartUpDataBase
   └─ UDataAsset_HeroStartUpData
```

核心字段：

```cpp
// 授予后按 OnGiven 策略自动执行，例如生成武器
TArray<TSubclassOf<UWarriorGameplayAbility>> ActivateOnGivenAbilities;

// 常驻等待事件/Tag 触发，例如后续 HitReact、Death
TArray<TSubclassOf<UWarriorGameplayAbility>> ReactiveAbilities;
```

`GiveToAbilitySystemComponent` 会依次调用 `GrantAbilities` 授予这两组能力；后续受击与死亡链依赖 `ReactiveAbilities`，不能只配置第一组。

核心函数：

```cpp
virtual void GiveToAbilitySystemComponent(UWarriorAbilitySystemComponent* InASCToGive,
                                          int32 ApplyLevel = 1);

void GrantAbilities(const TArray<TSubclassOf<UWarriorGameplayAbility>>& InAbilitiesToGive,
                    UWarriorAbilitySystemComponent* InASCToGive,
                    int32 ApplyLevel = 1);
```

授予：

```cpp
FGameplayAbilitySpec AbilitySpec(Ability);
AbilitySpec.SourceObject = InASCToGive->GetAvatarActor();
AbilitySpec.Level = ApplyLevel;
InASCToGive->GiveAbility(AbilitySpec);
```

`DA_Hero` 配置出生时的 `OnGiven` 能力，例如生成斧头。

### [P21 Synchronous Loading](https://www.bilibili.com/video/BV12YCrYCE62?p=21)（13:10）

**提交**：`d1883dd Sync loading done`。

角色字段：

```cpp

```

英雄初始化：

```cpp
if (!CharacterStartUpData.IsNull())
{
    if (UDataAsset_StartUpDataBase* LoadedData = CharacterStartUpData.LoadSynchronous())
    {
        LoadedData->GiveToAbilitySystemComponent(WarriorAbilitySystemComponent, 1);
    }
}
```

完整链：

```text
Controller Possess Hero
→ Base::PossessedBy
→ ASC.InitAbilityActorInfo
→ Hero::PossessedBy
→ CharacterStartUpData.LoadSynchronous
→ DA_Hero.GiveToAbilitySystemComponent
→ GiveAbility
→ OnGiven Policy 自动激活
→ GA_Hero_SpawnAxe
```

同步加载简单、顺序明确，但会阻塞游戏线程。单个英雄出生数据可以接受；大量敌人生成时课程后续改用异步加载。
